# 科研留痕

本技能按项目安装在 `.agents/skills/`，作用于所属项目；保留项目专属规则与适配，不创建用户级全局安装。

将研究经历保存为单一正文，区分测量事实、解释、决策和执行授权；保留负结果及后续修正，使未来检索能够回答“为什么做、做了什么、结果如何、为什么停止”。

## 选择工作范围

先检查目标项目的 AGENTS.md、现有归档规则和相关记录；已有规则优先复用，不另建平行账本。

- 用户要求在项目建立机制：执行“接入项目”。
- 用户要求记录或修正研究事件：执行“记录与收尾”；缺少机制时按当前授权创建最小记录结构，不顺带修改项目级代理规则。
- 用户只要复盘：优先使用并列的 weekly-retrospective 技能；未安装时使用本技能的精简复盘模板，不自动发布新的研究结论。
- 用户只要模板：交付所需 assets，不将模板占位内容发布为真实记录。

目标路径不明确且无法从会话确定时，询问路径，同时完成不依赖目标项目的模板整理。

## 接入项目

1. 盘点已有 records、索引、计划入口及发布器，优先适配已有结构；新项目默认使用 `docs/research/`。
2. 读取 [规则模板](assets/PROVENANCE.md)，按实际授权与工具能力适配后写入目标项目，并建立 `records/`、`templates/` 和用于复盘的 `weekly/`。
3. 将 [记录模板](assets/templates/record.md) 和 [复盘模板](assets/templates/retrospective.md) 放入目标项目 templates；若用户明确只要其中一部分，按所需范围交付。
4. 在用户要求项目接入时，将 [AGENTS片段](assets/AGENTS.fragment.md) 合并到现有 AGENTS.md，保留已有规则并避免重复；按实际目录调整所有引用。
5. 检查目录、链接、规则冲突及已有文件未被覆盖，报告实际创建或修改的路径。

本技能不含自动发布脚本；没有接入自动化时采用手工审阅与发布，不宣称启用了自动留痕、自动校验或遗漏检测。

## 记录与收尾

1. 按问题检索目标项目 records 中的支持、反例与适用条件；现有实验执行只读当前合同和必要记录，旧建议不授权重跑。
2. 遵循目标项目 PROVENANCE；缺少规则时读取 [规则模板](assets/PROVENANCE.md)，并使用 [记录模板](assets/templates/record.md) 起草。
3. 记录正/负/未定结果、重要失败、协议或假设变化、放弃方向及影响结论的代码/数据问题；纯格式整理不新增记录。
4. 为关键测量注明数据版本、对照、分母、指标、来源位置和核验等级；事件日期与写入日期分开，未知动机或缺失证据如实注明。
5. 发布前核对可访问来源的SHA-256及定位，核对关键数字与原报告一致，并检查关系ID确实存在；哈希一致仅说明字节身份，不证明科学结论。
6. 有项目发布器时按其文档、已验证的项目运行环境执行发布及索引检查；没有发布器时检查ID未占用后保存 `records/<ID>.md`，明确为手工检查。
7. 同ID同正文视为幂等，异内容使用新ID与 corrects/supersedes 关系追加，保留旧记录及负结果。

归档不触发模型推理、重训、发布release或外部消息；可变来源优先引用冻结快照，大型原件通过紧凑回执关联并披露未复核范围。

收尾报告记录ID、路径和实际检查；无实质研究变化用 `NO_RESEARCH_DELTA` 加原因，失败用 `ARCHIVE_PENDING` 加原因及草稿/产物位置，不为归档失败重跑实验。

## 简明复盘

使用 [复盘模板](assets/templates/retrospective.md)：Hypothesis一句话，Design每点一句话，Result用最小充分表格，Conclusion每点一句话，并链接源记录。

复盘是派生摘要；新决定或重要修正先按“记录与收尾”建立来源，再更新摘要，普通摘要重写不制造新实验记录。
