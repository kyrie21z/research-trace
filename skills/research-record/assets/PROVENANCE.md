# 记录与证据规则

## 权威边界

- `records/` 保存唯一的研究经历正文；实验产物提供测量事实，协议规定实验约束，当前任务指令提供执行授权。
- 复盘是带来源的摘要，不替代原记录；历史建议和归档动作不授权重跑实验。
- 实质变化及时记录：正/负/未定结果、有价值的失败、协议与假设变化、放弃方向、影响结论的代码或数据问题。
- 纯格式整理无需新记录；收尾说明 `NO_RESEARCH_DELTA` 及原因。

## 最小记录

每条记录使用稳定且唯一的ID和五节正文：问题与动机、尝试与条件、观察与证据、解释与经验、关联与后续修正。

正文每个要点优先一句话，结果优先最小充分表格；完整日志、预测和大文件留在实验产物中，只引用紧凑报告或回执。

元数据中 recorded_at 为实际写入时间，occurred_at 为有依据的事件时间；未知事件时间使用 null 并说明，原始动机未知时直接写未知。

scope 明确数据/版本/方法/指标/预算及适用范围；不同协议的结果分开比较，执行成功、效果改善、机制解释和项目采纳分开陈述。

## 来源

来源写明项目相对路径、段落/行号/JSON键、SHA-256和核验等级；远端或缺失来源写明位置与缺口，不编造指纹。

| status | 含义 |
|---|---|
| artifact_checked | 实际检查过原始产物，仅覆盖已检查部分 |
| report_checked | 读取了既有报告，未据此声称原始测量已重算 |
| code_only | 只见实现，未证明运行或效果 |
| conversation_only | 讨论或口头陈述，不能作为实测证据 |
| snapshot_checked | 核对过历史文本快照，未升级为原始测量验证 |
| remote_only / missing / unverified | 来源不可本地核验，必须填写 reason |

发布前核对来源位置与内容，必要时用 `sha256sum <证据文件>` 计算指纹；本地实际检查过的来源必须提供真实指纹。

引用易变计划或报告时优先使用冻结快照；不把密钥、凭据、个人敏感信息写入记录，快照也应只保留任务必要内容。

## 发布与修正

1. 按模板写草稿，检查必填字段、关键数字、分母、单位、适用范围和来源等级。
2. 检查ID未占用及 related/corrects/supersedes 目标存在，将审阅后的文件存为 `records/<ID>.md`。
3. 同ID同正文可视为幂等完成，同ID不同正文须新建修正记录，保留旧文件。
4. 重要错误用 corrects，明确替代旧阶段或方案用 supersedes，一般关联用 related；关系不自动跨作用域撤销旧结论。
5. 手工模式报告记录ID、路径与实际检查项；自动模式另运行所属发布器及索引检查，未运行的校验不标PASS。
6. 归档失败报告 `ARCHIVE_PENDING`、原因与草稿/产物位置，修复归档即可，不为归档重跑实验。
